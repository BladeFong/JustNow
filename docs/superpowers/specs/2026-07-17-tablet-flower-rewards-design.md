# JustNow 平板端时光胶囊与七朵花花瓣奖励机制设计规范

## 1. 概述 (Overview)
为了在平板模式下更好地引导儿童居家习惯培养，本项目引入一套将“物理记录（拍照成果）”与“游戏化习惯（收集花瓣点亮小花）”相结合的非主流积分奖励机制。
当儿童完成任务时，应用弹出色彩自适应的祝贺弹窗并播放音画一致的鼓励语音，引导家长协助孩子拍照记录成果。拍好的照片存入专属系统相册，并在应用内形成“时光胶囊照片墙”进行安全回顾；同时，每次拍照将根据任务所属的四象限优先级为今日花朵增加不同数量的花瓣，每周拼满 5 朵花即算挑战成功。

---

## 2. 数据与逻辑层设计 (Data & Storage Architecture)

### 2.1 照片物理存储设计
*   **存储位置**：使用 Android `MediaStore` API 将照片写入外部共享存储的公有相册下专属目录：`/sdcard/Pictures/JustNow/`。
*   **照片命名**：`IMG_JustNow_[任务英文简称]_yyyyMMdd_HHmmss.jpg`。
    *   *说明*：英文简称优先使用任务已绑定的内置儿童图标名 `icon_name`（如 `study`, `music`, `book`）；若任务未绑定图标，则根据象限优先级使用默认分类英文（如 `q1`, `q2`, `q3`, `q4`）。
*   **独立性**：照片保存在系统公有相册中，即便系统相册被家长添加了应用锁，应用也能通过私有 URI 或媒体读取权在应用内时光胶囊进行独立回顾。

### 2.2 数据库 Schema 变更与迁移
在 Room 数据库中新增一张关联表 `task_photos`，建立任务、照片和时光胶囊的绑定：
*   **数据库版本**：从 `8` 升级至 `9`。
*   **数据表定义**：
    ```sql
    CREATE TABLE task_photos (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        task_id INTEGER NOT NULL,          -- 关联的任务ID (TaskEntity)
        photo_uri TEXT NOT NULL,           -- 系统相册中照片的 Uri 路径
        created_at INTEGER NOT NULL,       -- 拍摄时间戳 (用于周筛选与排序)
        FOREIGN KEY(task_id) REFERENCES tasks(id) ON DELETE CASCADE
    );
    ```
*   **升级脚本 (Migration_8_9)**：
    ```java
    private static final Migration MIGRATION_8_9 = new Migration(8, 9) {
        @Override
        public void migrate(@NonNull SupportSQLiteDatabase database) {
            database.execSQL("CREATE TABLE IF NOT EXISTS `task_photos` (" +
                    "`id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, " +
                    "`task_id` INTEGER NOT NULL, " +
                    "`photo_uri` TEXT NOT NULL, " +
                    "`created_at` INTEGER NOT NULL, " +
                    "FOREIGN KEY(`task_id`) REFERENCES `tasks`(`id`) ON DELETE CASCADE)");
        }
    };
    ```

### 2.3 时光胶囊周期与防裂图自愈机制
*   **花瓣周重置**：每周一 00:00 自动开启新一轮的时光胶囊统计。界面上的“X/7 朵花”仅根据本周一 00:00 至本周日 23:59:59 期间完成任务并成功拍照的历史进行点亮判断。
*   **防裂图自愈**：在“时光胶囊”照片墙或主页加载数据时，后台异步使用 `ContentResolver` 校验每个 `photo_uri` 对应照片的物理存在性。若用户已在外部相册删除了该照片，应用会自动删除 `task_photos` 表中的对应记录，实现数据的防错与自动对齐。

## 3. UI 与交互设计 (UI & Interaction Design)

### 3.1 任务完成祝贺弹窗 (Congratulation Dialog)
*   **色彩象限自适应**：祝贺弹窗的背景、高亮按钮及图标文字，自动使用该任务所属象限的标志色（如：完成第一象限任务，弹窗呈现 Q1 红色系主题）。
*   **音画一致语音播报**：内置清脆可爱的系统童声语音。当弹窗出现时，语音只播报并完全朗读弹窗上的正文文字内容：“您好棒，快去让爸爸妈妈帮忙，拍照记录成果吧！”，帮助孩子在听觉与认读上保持一致。

### 3.2 每日花朵花瓣拼满机制 (胖胖花几何数学定义)
每朵花需要收集满 **5 片花瓣** 才能点亮。
*   **四象限花瓣权重**：
    *   Q1 任务（重要且紧急）➡ 拍照后获得 **3 片花瓣** 🌸🌸🌸。
    *   Q2 / Q3 任务（重要/紧急）➡ 拍照后获得 **2 片花瓣** 🌸🌸。
    *   Q4 任务（不紧急不重要）➡ 拍照后获得 **1 片花瓣** 🌸。
*   **几何无交叉外切胖胖花 (Canvas 绘制参数)**：
    为保证虚线状态不晃眼，花瓣采用正圆相切，且去除接触处的黑切线。
    *   *花芯（始终实线填充）*：圆心 `(50, 50)`，半径 $R_c = 15.5$。始终使用实线勾边并用亮黄色（`#FFEB3B`）填充。
    *   *花瓣（开口免切线）*：半径 $R_p = 17$，圆心距中心 $d = 29$。底角起点与终点精准定位在花芯的 5 等分点处，即 $A(-9.1, -12.5)$ 和 $B(9.1, -12.5)$。
    *   *绘制逻辑*：使用 Path 绘制花瓣时**不调用 `close()` (不画 `Z` 连线)**。底端开口直接与花芯边缘衔接。
    *   *虚线样式*：未点亮的花瓣使用大线段、大间距虚线：`DashPathEffect(new float[]{8f, 6f}, 0f)`。

### 3.3 “七朵花”主界面自适应布局
7 朵花的容器（`flower_capsule_container`）嵌套在右侧栏 `right_panel` 的内部，不影响全局横贯底部的 `bottom_period_bar`：
*   **平板竖屏下**：7 朵花在 `right_panel` 的最底部呈**横向一排**展示（任务列表网格下方）。
*   **平板横屏下**：7 朵花在 `right_panel` 的最右侧呈**竖向一列**展示（任务列表网格右侧）。
*   **无多余文字**：去除周一至周日等星期标签，纯展示 7 朵花及其点亮状态（当天已集满 5/5 瓣的花朵呈现全填充并带有亮光小动效，未集满的按当前瓣数实虚相贴展示）。

### 3.4 右上角设置菜单入口
在主界面右上角 Overflow 菜单中新增“时光胶囊设置”：
*   **祝贺语音开关**：全局开启/关闭祝贺提示音与朗读语音。
*   **自动保存开关**：是否自动向系统公共相册写入照片（默认开启）。
*   **本周成功目标**：默认为 **5 朵花**。当本周集满 5 朵花时，在周日解锁终极大奖弹窗。

## 4. 测试用例与边界处理 (Test Cases)
1. **数据库迁移无损测试**：从 version 8 升级至 9 时，验证原有任务表数据不丢失，新表 `task_photos` 正确建立。
2. **照片不存在边界测试**：手动在系统相册中删除一张照片，重新打开应用时光胶囊，验证该卡片自动消失，且花瓣数计数同步校正，不发生崩溃和显示异常。
3. **横竖屏旋转布局重载测试**：平板在横竖屏旋转时，验证 7 朵花能正确在“最底部横排”与“最右侧竖排”之间重载切换，数据状态完整。
