# 平板端任务扫码传图系统设计规范

## 1. 背景与目标

### 1.1 背景
在平板端（JustNow）的儿童奖励与时光胶囊系统中，任务（特别是户外打卡活动）通常在未携带平板的情况下进行，无法使用平板即时拍照。用户希望在手机端**不安装额外 APP**的前提下，快速将手机拍摄的照片发送给平板并与指定任务关联。

### 1.2 目标
- **极简三步交互**：平板展示二维码 → 手机原生扫码选图 → 点击发送秒传。
- **全平台零安装**：适用于 iOS (iPhone Safari)、Android 各品牌 (Chrome / 华为 / 小米 / OPPO / vivo / 三星等原生扫码与相册)，基于标准 HTML5。
- **局域网直连**：支持家庭 Wi-Fi 及手机个人热点，零云端中转服务器成本，高隐私安全与极速内网传输。
- **业务闭环**：照片入库 `task_photos`，关联任务并刷新七朵花花瓣奖励（注：点亮动画及 TTS 语音播报已于此前精简中取消）。

## 2. 交互设计与三步操作流

```
【第一步：平板展示二维码】
平板任务列表 (TaskPhotoListDialog) ──> 点击「扫码传图」 ──> 弹出 QrUploadDialog (展示任务标题、图标、二维码、剩余名额)

【第二步：手机扫码与选图】
手机自带相机/扫码 ──> 自动在浏览器打开平板 H5 页面 ──> 点击「+」调起系统相册多选 (1~N 张，N 为该任务剩余可传名额)

【第三步：点击发送并闭环】
手机点击「确认发送」 ──> 页面提示“发送成功” ──> 平板自动保存照片至私有目录并入库、刷新花朵与任务状态、自动关闭二维码弹窗
```

### 2.1 平板端交互规范
- **入口**：在 `TaskPhotoListDialog`（拍照任务列表）每个任务项右侧，在原有的「📷 拍照」按钮旁新增「📱 扫码传图」按钮。
- **二维码弹窗 (`QrUploadDialog`)**：
  - **顶部**：显示任务标题、分类图标、所属象限颜色条。
  - **中部**：展示动态生成的局域网 URL 二维码（`http://<IP>:<Port>/upload?taskId=xxx&token=yyy`）。
  - **底部状态指示**：
    - 初始状态：“等待手机扫码...” 及剩余可传名额（如：“还可以上传 3 张照片”）。
    - 手机扫码后：“🟢 手机已连接，正在选图中...”。
    - 接收成功后：“🎉 成功接收 N 张照片！”，1.5 秒后自动关闭弹窗。
- **生命周期与休眠**：
  - 动态读取系统屏幕休眠时间：`Settings.System.getInt(resolver, Settings.System.SCREEN_OFF_TIMEOUT, 60000)`。
  - 有效超时上限封顶：`effectiveTimeout = Math.min(systemScreenOffTimeout, 3 * 60 * 1000L)`。
  - 手机连接期间临时保持常亮（`FLAG_KEEP_SCREEN_ON`）；心跳丢失后立即释放常亮锁，随系统自然休眠。

### 2.2 手机端 H5 交互规范 (`upload.html`)
- **任务卡片**：顶部显示任务标题与所属分类图标，标明“当前任务最多可上传 5 张，还可以上传 N 张”。
- **相册选择与预览**：
  - 标准 HTML5 `<input type="file" accept="image/*" multiple>` 唤起原生相册。
  - 九宫格网格预览选中图片，支持单张右上角「✕」移除重选。
  - 超过剩余名额时，前端自动截断多余选图并给出友好提示。
- **状态感知与错误提示**：
  - 未选照片时「确认发送」按钮置灰。
  - 上传中展示圆形进度条与百分比。
  - 上传完成后展示绿色成功状态卡片，禁用重复提交。
  - 异常断开时显示明确错误提示。

## 4. 双端对等心跳与异常状态机

### 4.1 心跳协议规范
- **接口**：`GET /api/ping?taskId={id}&token={token}`
- **频率**：手机端加载页面后，每 **1 秒**（1000ms）向平板发送一次 ping，请求超时时间设为 2000ms。
- **平板端响应**：返回 `200 OK`，并更新 `lastHeartbeatTimestamp`。

### 4.2 状态对等判断（5 秒容错判定）

| 状态阶段 | 手机端响应 | 平板端响应 |
|---|---|---|
| **连续 1~2 次失败 (1~2s)** | 静默自动重试，界面不打扰（兼容相册调起与 Wi-Fi 节能休眠） | 保持“手机已连接”状态 |
| **连续 3 次失败 (3s)** | 页面顶部浮现弱提示：“正在尝试重新连接平板...” | 保持“手机已连接”状态 |
| **连续 5 次失败 (5s)** | 判定彻底断开，界面切为红色错误提示并禁用发送 | 判定手机已离线，状态切回“等待手机扫码...”，释放常亮锁 |
| **中途成功恢复 (<5s)** | 失败计数清零，恢复正常绿色连接状态 | 刷新 `lastHeartbeatTimestamp`，保持常亮 |

## 5. 图片压缩与存储规范

### 5.1 手机端 Canvas 压缩策略（确保 < 3MB，极速秒传）
- **原图大小 <= 3MB**：跳过 Canvas 压缩，直接以原始 Blob 上传（保持 0 损耗）。
- **原图大小 > 3MB 或超高分辨率**：
  - 限制长边最大为 2048px，按原图宽高比等比缩放。
  - 使用 `canvas.toBlob(blob, 'image/jpeg', 0.92)` 导出 JPEG。
  - 重采样后体积稳定在 800KB ~ 1.8MB 之间，耗时 < 50ms。

### 5.2 平板端文件存储与持久化
- **存储路径**：`context.getExternalFilesDir(Environment.DIRECTORY_PICTURES)`
- **文件命名规则**：`photo_task_{taskId}_{System.currentTimeMillis()}_{index}.jpg`
- **流式写入**：服务端通过 `InputStream` 边读边写入磁盘，单张图片上限 20MB，避免一次性载入内存引发 OOM。若网络意外中断，自动删除未写完的残缺临时文件。
- **Room 数据入库**：批量执行 `mPhotoRepository.bindPhotoToTask(taskId, fileUri)`。
- **上限校验**：单任务已有照片数 + 本次上传数严格限制 <= 5 张。

## 6. 安全校验与端口冲突防御

1. **随机 Session Token**：每次打开 `QrUploadDialog` 动态生成 8 位随机 Token，验证不通过时返回 `403 Forbidden`。
2. **格式白名单**：严格仅放行 `image/jpeg`、`image/png`、`image/webp`、`image/heic`。
3. **端口自适应**：默认尝试绑定 `8888` 端口；若被占用，自动递增探测 `8889 ~ 8899`，以最终实际绑定的端口生成二维码 URL。
4. **生命周期零残留**：无论通过点击关闭、休眠超时、或上传完成，均触发 `server.stop(0)`，彻底释放端口与线程池。
